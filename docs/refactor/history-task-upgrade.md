# 历史记录与视频任务升级

## 使用方式

历史页每页显示 20 条记录，提供总数与上一页／下一页；后端查询全部匹配记录，不再仅在最近 100 条中筛选。
支持图片／视频、任务状态、文件名／作物／虫种关键词及日期区间。日期以浏览器本地日期为准，包含所选结束日；API 结束时间为排他边界，时区先换算成 UTC。
筛选与页码写入地址栏，刷新及浏览器前进后退可恢复。清空仍删除全部记录，确认框明确包含筛选之外的记录。

视频卡片显示等待、准备、逐帧识别、转码阶段，以及已处理帧数与帧进度。帧进度不等于转码或 AI 分析进度。
失败视频若保留源文件可点击“重试视频”，复用原任务记录；没有源文件时需重新上传。
在“失败”状态筛选下，重新排队的任务会离开当前筛选，可切换至全部状态或视频页查看进度。

## 实现与恢复边界

- 新接口 GET /api/detections/search 返回 items、total、offset、limit；原列表 API 保持兼容。
- 新接口 POST /api/videos/{id}/retry 校验归属、状态及源文件；重复请求不会重复创建任务。
- 进度保存在已有 video_meta 中，响应提供 progress 字段，无需数据库迁移。
- 工作线程按帧更新内存快照，后台约每 2 秒保存进度与心跳；写入受任务尝试编号和状态约束，旧任务不能覆盖新结果。
- 正常关闭服务会中断视频并保留源文件、重新排队，下次启动继续处理。
- 异常进程退出后的失联任务仍由巡检判定超时；失败后可用保留源文件手动重试。不是从中间帧断点续算，重试会重新处理该视频。
- 本地执行器遇到暂时的数据库巡检异常会继续重试，不因单次异常退出。
- 视频页向后端按视频类型查询，避免大量图片挤掉较早的视频任务。

## 验证

188 项后端测试通过；原 React 24 项流程通过；新增 14 项浏览器检查通过。
新增浏览器数据集为 126 条隔离记录，验证了第 100 条之后的旧记录检索、中文虫种搜索、日期、状态、页码恢复、视频重试和帧进度。
测试使用模拟检测／AI和实际本地任务执行器；未调用付费模型。关闭与恢复通过取消工作任务后重新执行验证，不代表已经验证所有断电和硬件故障场景。
